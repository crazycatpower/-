行動裝置職安稽核模型　第 6 版成效

以工地現場照片自動判定職業安全合規性的微調模型。本報告比對 v1 初版與 v6 的偵測表現，並附 6 張全新照片的完整流程實測。

日期 2026-09-09 底模 Gemma 3n E2B 評測集 100 張標註照片 硬體 單張 RTX 3060

結論摘要

召回率翻倍，精確率不變

對安全稽核而言，「漏抓危害」（false negative）比「誤報」代價更高。v6 在不犧牲精確率的前提下，把召回率從初版的 0.42 拉到 0.63。

Accuracy · 準確率 78% ▲ +6.4 pt vs v1 整體判斷正確比例
Precision · 精確率 81% ± 0 pt vs v1 判為「有缺失」時的正確率
Recall · 召回率 63% ▲ +22 pt vs v1 實際有缺失的案例中被抓到的比例

v5（2 epoch，108 步） v6（3 epoch，234 步）

v6 訓練末段 loss（~0.08–0.11）明顯低於 v5 收斂區間，entropy 掉到 0.068——單看訓練曲線像是過擬合；但 100 張評測集上 v6 recall 仍優於 v5（0.63 對 0.53），且對照組 checkpoint-100 表現更差，說明這段額外訓練是有效學習而非單純記憶。

技術附錄

方法與論文依據

今天實際動到的技術，依「v5 改動 / v6 改動 / 否定結論 / 底層方法」分類，附對應文獻。

v5 改動 · 關鍵

訓練／推論格式對齊

舊版訓練 prompt 為純文字，推論時卻在 prompt 內塞一大段 YOLO 偵測框清單 — 對模型是 out-of-distribution 輸入，實測讓召回率從 0.56 掉到 0.41。v5 改成訓練時就用同一支 YOLO 對每張訓練圖跑真實偵測，把清單逐字接在 prompt 後，格式與推論 byte-for-byte 一致；system prompt 與輸出 JSON schema 三邊對齊。

train–serving skew。把物件偵測結果當文字證據餵給視覺模型以強化 grounding，概念近 Set-of-Mark Prompting（Yang et al. 2023, arXiv:2310.11441）。
v5 改動

Completion-only 損失遮罩

舊版只遮 padding，等於逼模型連 system prompt、半模板化的 YOLO 清單、甚至圖片 soft token 都要「學會生成」— 浪費容量，且模板化文字會拉高生成時卡重複迴圈的機率。v5 把 assistant 回答之前的所有 token（含 image placeholder）label 設為 −100，只在 JSON 答案上算 loss。

指令微調標準做法。LLaVA 視覺指令微調（Liu et al. 2023, arXiv:2304.08485）只在 assistant response 算 loss；LIMA（Zhou et al. 2023, arXiv:2305.11206）指出對 prompt 算 loss 會傷品質。
v5 改動 · 工程

梯度檢查點（解 12GB OOM）

RTX 3060 12GB 跑 QLoRA ＋ 視覺塔 ＋ 896px 影像，第 15 步 CUDA OOM，還會先溢出到 shared memory 讓每步從 90s 爬到 155s。開 gradient_checkpointing（use_reentrant=False）後前向不存中間 activation、反向時重算，以計算換記憶體，每步反而降到約 55s。

activation recomputation / sublinear memory — Chen et al. 2016,「Training Deep Nets with Sublinear Memory Cost」, arXiv:1604.06174。
v6 改動 · 關鍵

少數類別（有缺失）過採樣 ×2

對安全稽核，漏抓危害（false negative）比誤報代價高，而 v5 精確率 0.80 仍有餘裕。v6 在 train split 把 compliant=false 樣本複製一份（violation:compliant 由 45:55 → 約 62:38），把決策邊界推向「敢開缺失」。召回率 0.53 → 0.63，精確率維持。

類別不平衡下的 minority oversampling / cost-sensitive learning；動機同 Focal Loss（Lin et al. 2017, arXiv:1708.02002），此處用最樸素的重複採樣而非 focal loss 或 SMOTE。
v6 改動

訓練輪數 2 → 3 ＋ checkpoint 對照驗證

v5 結束時 loss 仍在下降，未充分收斂，v6 加一輪。final 的 train entropy 掉到 0.068 看似過擬合，但評測 checkpoint-100（僅訓練一半）召回率只有 0.34、final 為 0.63 — 證明提升來自完整訓練而非記憶訓練集。

checkpoint selection / early-stopping 標準方法論。
否定結論

推論端抑制重複 → 精確率崩，不可用

剩餘的 JSON 解析失敗來自 YOLO 零偵測圖的重複迴圈。試 repetition_penalty=1.3 召回率升到 ~0.86 但精確率掉到 ~0.41；no_repeat_ngram_size=4 召回率 ~1.0、精確率 ~0.44、真陰性只剩 1。因為合規答案 {"compliant":true,"findings":[]} 又短又高頻，全域抑制重複會把機率質量從它推開。此問題須在訓練端或以「解析失敗→轉人工複核」處理。

貪婪解碼退化成重複迴圈 — Holtzman et al. 2019, arXiv:1904.09751。repetition_penalty — CTRL, Keskar et al. 2019, arXiv:1909.05858。n-gram 阻擋 — Paulus et al. 2017, arXiv:1705.04304。
底層方法

QLoRA（4-bit NF4 ＋ LoRA rank 32）

4-bit NF4 量化凍結底模，只訓練掛在 q/k/v/o/gate/up/down 投影上的低秩適配器；搭配 8-bit 分頁 AdamW 優化器避免記憶體尖峰。全程單張消費級 GPU。

LoRA — Hu et al. 2021, arXiv:2106.09685。QLoRA（NF4 / 雙重量化 / 分頁優化器）— Dettmers et al. 2023, arXiv:2305.14314。8-bit 優化器 — Dettmers et al. 2021, arXiv:2110.02861。
底層方法

底模 Gemma 3n E2B

Google on-device 多模態模型，檔案 5.4B 參數但有效約 2B — 靠 MatFormer（巢狀 / 可伸縮 Transformer）與 Per-Layer Embeddings（把嵌入參數卸到快取）達成；視覺塔為 MobileNet-V5。前處理的物件偵測用 Ultralytics YOLO。

Gemma 3 技術報告 — arXiv:2503.19786。MatFormer — Kudugunta et al. 2023, arXiv:2310.07707。YOLO 原始概念 — Redmon et al. 2016, arXiv:1506.02640。

模型　gemma4-e2b-audit-lora-v6/final　·　底模 google/gemma-3n-E2B-it　·　QLoRA rank 32　·　3 epochs　·　train 620 / val 57

評測方法　100 張取自 483 張標註資料集（固定亂數種子）；輸入為現場照片 + YOLO 物件清單；以模型輸出 JSON 的 findings 是否為空判定「有無缺失」，與答案的 violation 欄位比對。貪婪解碼，未加抑制重複參數（實測會嚴重犧牲精確率）。
